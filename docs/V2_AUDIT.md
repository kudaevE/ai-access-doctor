# AI Access Doctor V2.0 — Аудит существующей кодовой базы (V1.0)

**Дата аудита:** 17 октября 2026  
**Версия системы:** Windows 11 Pro x64 (Build 26200)  
**Стек:** Tauri 2.0 (Rust backend), React 18, TypeScript, Tailwind CSS, SQLite (rusqlite), Tokio.

---

## 1. Архитектура и структура существующего проекта

### 1.1 Backend (Rust / Tokio / Tauri)
- **`src-tauri/src/lib.rs`**: Главная точка входа IPC Tauri, объявление структуры состояния `AppState` (хранит `DiagnosticStorage` с мьютексом), регистрация команд:
  - `run_full_diagnostics(proxy_override: Option<String>)`: Последовательно опрашивает сетевые адаптеры, DNS, WinINet/WinHTTP/Env прокси, VPN-туннели, 5 ключевых AI-сервисов, вычисляет вердикт через движок правил и сохраняет в SQLite.
  - `get_network_info()`, `get_proxy_info()`, `get_vpn_info()`: Точечные диагностические команды.
  - `get_history(limit: Option<usize>)`, `get_report_by_id(id: String)`: Выборка из локальной SQLite БД.
  - `export_report(id: String, sanitize: bool, format: String)`: Экспорт в Markdown/JSON с очисткой конфиденциальных данных.
- **`src-tauri/src/diag/`**:
  - `network.rs`: Опрос физических и виртуальных интерфейсов, шлюзов, DNS через Windows IP Helper API (`GetAdaptersAddresses`) и сокетный зонд dual-stack (IPv4/IPv6 RTT).
  - `dns.rs`: Параллельное сравнение системного резолвера и независимых резолверов (Cloudflare DoH / 1.1.1.1, Google 8.8.8.8, Quad9 9.9.9.9), фиксация расхождений и подмены IP.
  - `proxy.rs`: Чтение параметров WinINet из реестра (`HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings`), опрос WinHTTP через `netsh winhttp show proxy`, чтение переменных окружения (`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY`), проверка доступности портов прокси и возможность туннелирования HTTPS.
  - `vpn.rs`: Обнаружение виртуальных адаптеров (Wintun, TAP, WireGuard, Tailscale) и анализ дефолтных маршрутов таблицы маршрутизации (`0.0.0.0/0`) на предмет конфликтов метрик.
- **`src-tauri/src/services/`**:
  - `mod.rs`: Профили для 5 основных провайдеров AI (Google Antigravity, Google Gemini, OpenAI/Codex, Anthropic Claude, GitHub Developer Services) с разделением статусов: Pass, AuthBoundary (401), RateLimited (429), DnsFailure, TcpFailure, TlsFailure, ProxyFailure, GeoBlocked (403/451).
- **`src-tauri/src/engine/rules.rs`**:
  - Детерминированный логический вывод вердикта без галлюцинаций. Содержит 9 unit-тестов, проверяющих типовые сбои (полный обрыв сети, мертвый прокси-порт, конфликт переменных окружения, DNS-блокировка, DNS-подмена нивелированная прокси, TLS MITM, Geo-IP блокировка, коллизия метрик VPN, штатное состояние).
- **`src-tauri/src/storage/db.rs`**:
  - SQLite хранилище (`ai_doctor.db`), автосоздание схемы, санитайзер секретов (маскирование Bearer токенов, ключей `sk-...`, `ghp_...`, паролей и чувствительных IP).

### 1.2 Frontend (React / TypeScript / Tailwind CSS)
- **`src/types/index.ts`**: Полная строгая типизация ответов бэкенда и моделей данных.
- **`src/App.tsx`**: Корневой компонент с управлением вкладками, подпиской на события прогресса `diag-progress`, интеграцией демо-режима и вызовами IPC.
- **`src/components/`**:
  - `Sidebar.tsx`: Боковая навигация с бейджами статуса и индикатором текущего вердикта.
  - `Header.tsx`: Верхняя панель со статусом, кнопкой запуска диагностики, экспортом и переключателем демо-режима.
  - `DashboardView.tsx`: Главный дашборд с баннером вердикта, метриками и карточками сервисов.
  - `AiServicesView.tsx`: Детализация состояния каждого сервиса и его эндпоинтов.
  - `NetworkProxyView.tsx`: Детальный анализ интерфейсов, шлюзов, DNS и прокси (WinINet, WinHTTP, Env).
  - `VpnRoutingView.tsx`: Таблица маршрутов и обнаруженные виртуальные туннели.
  - `ErrorAnalysisView.tsx`: Корневая причина, технические свидетельства и пошаговые рекомендации.
  - `HistoryReportsView.tsx`: История запусков, экспорт отчетов и просмотр архива.
  - `SettingsView.tsx`: Ручное переопределение прокси и очистка истории.

## 2. Выявленные недочеты и точки роста для V2.0

1. **Метрика достоверности (Confidence)**:
   - В V1.0 использовались числовые проценты (например, 94%, 96%, 100%), которые могут восприниматься пользователем как субъективные или произвольные.
   - Для V2.0 необходимо ввести категориальную шкалу силы доказательств (`CONFIRMED_FACT`, `STRONGLY_SUPPORTED`, `HYPOTHESIS`, `INCONCLUSIVE`) с прозрачным списком подтвержденных фактов.

2. **Точность статусов ИИ-сервисов**:
   - В V1.0 сервисы отображались как "pass / warning / fail". В V2.0 требуется 5 явных состояний:
     - `AVAILABLE` (полностью доступен, 200 OK)
     - `AUTH REQUIRED` (сеть исправна, HTTP 401 Auth Boundary)
     - `DEGRADED` (высокий пинг, лимиты 429 или частичный отказ одного из эндпоинтов)
     - `UNAVAILABLE` (TCP timeout, 5xx, блокировка)
     - `UNKNOWN` (не проверялся / нет связи)

3. **Отсутствие модуля анализа произвольных ошибок (Smart Error Detective)**:
   - В V1.0 пользователь мог видеть только результат собственного аудита. Нет окна для вставки сырых логов из терминала или IDE (`ECONNRESET`, `502 Bad Gateway`, `ETIMEDOUT`, `401 Unauthorized`, `Self-signed certificate in certificate chain`).
   - Требуется реализовать P0-модуль с локальным парсером ошибок, санитайзером и формированием точной причины и рецепта решения.

4. **Отсутствие сравнительного анализа каналов (Connection Comparison)**:
   - Пользователь часто не понимает, почему через браузер работает, а через терминал или Cursor — нет. Требуется матрица сравнения: Прямое соединение vs Системный прокси vs Кастомный прокси vs DoH vs VPN.

5. **Отсутствие безопасного движка применения исправлений (Safe Fix Engine)**:
   - В V1.0 даются только текстовые команды для ручного копирования. Пользователю требуется возможность нажать "Устранить проблему" с обязательным окном предварительного просмотра (Dry Run), подтверждением и созданием снимка отката (Rollback).

6. **Отсутствие IDE & MCP Doctors**:
   - Разработчики сталкиваются со специфическими сбоями в конфигурациях Cursor, VS Code, Zed, Windsurf, JetBrains и MCP-серверах (stdio / SSE). Необходим специализированный аудит конфигов и путей.

7. **Дизайн-система**:
   - Текущий UI опрятен, но требует эволюции в эстетику high-end developer tools (Linear / Raycast / Vercel): глубокая темная палитра `#0B1019` / `#151E2D` / `#223047`, акцент `#39BDF8`, утонченная типографика, компактная сетка метрик и интерактивные графики латентности.

## 3. Совместимость и план сохранения функционала
- Все имеющиеся тесты (9/9) в `src-tauri/src/engine/rules.rs` должны продолжать выполняться.
- Существующая база SQLite (`ai_doctor.db`) сохраняет обратную совместимость через расширение схемы без удаления существующих полей.
- Никаких скрытых или небезопасных системных изменений. Принцип безопасности: **Read-Only Diagnostics By Default**.
