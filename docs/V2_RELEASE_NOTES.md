# AI Access Doctor V2.0 — Release Notes & Technical Documentation

**Дата релиза:** 17 октября 2026  
**Версия:** 2.0.0 (Windows 10/11 Desktop Platform)  
**Статус:** Verified Production Release  

---

## 1. Обзор релиза V2.0

Версия **AI Access Doctor V2.0** представляет собой комплексную эволюцию от инструмента диагностики в полноценную настольную платформу наблюдаемости и безопасного устранения сетевых неполадок для разработчиков искусственного интеллекта.

Интерфейс приложения переработан в соответствии с визуальной эстетикой ведущих профессиональных инструментов разработчика (Linear, Raycast, Vercel Dashboard, Grafana).

## 2. Реализованные ключевые возможности

### 2.1 P0: Обновленный дашборд и объективная сила доказательств (Evidence Strength)
- **5 ключевых карточек метрик**:
  1. *Состояние подключений*: Мгновенный статус (В норме / Внимание / Сбой) с точным кодом первичной аномалии.
  2. *Доступные AI-сервисы*: Четкий счетчик готовых к работе сервисов (например, `5/5`).
  3. *Предупреждения*: Количество предупреждений по задержкам и квотам.
  4. *Средняя задержка*: Задержка в миллисекундах с качественной оценкой отклика.
  5. *Последний аудит*: Время последнего замера.
- **Отказ от произвольных процентов уверенности**:
  - Введена категориальная шкала: `CONFIRMED_FACT` (Подтвержденный факт), `STRONGLY_SUPPORTED` (Высокая вероятность), `HYPOTHESIS` (Гипотеза), `INCONCLUSIVE`.
  - Прозрачный блок объективных подтвержденных фактов.
  - Честное информирование: если системный DNS подменяется цензурой провайдера, но нейтрализуется прокси с удаленным резолвингом, система фиксирует это как рабочий статус с подробным разъяснением, а не как фатальный сбой или ложное «все чисто».
- **5-состояний доступности сервисов**:
  - `AVAILABLE` (Полностью доступен, 200 OK)
  - `AUTH REQUIRED` (Сетевой доступ исправен, HTTP 401 Auth Boundary)
  - `DEGRADED` (Высокая задержка или лимиты 429)
  - `UNAVAILABLE` (TCP timeout, 5xx, блокировка)
  - `UNKNOWN` (Не проверен)
- **История стабильности**:
  - Интерактивная лента стабильности запусков на базе SQLite.

### 2.2 P0: Smart Error Detective (Детектив сетевых ошибок и логов IDE)
- Возможность вставки произвольного фрагмента лога или текста ошибки из терминала, Cursor, VS Code, Python, Node.js, Git.
- Поддержка импорта файлов `.log`, `.txt`, `.json`.
- Автоматическая локальная санитизация секретов (маскирование ключей `sk-...`, `Bearer`, `ghp_...`, паролей и имен пользователей).
- Детерминированный анализатор сигнатур:
  - HTTP 400, 401, 403, 404, 408, 429, 500, 502, 504.
  - Сокетные сбои: `ECONNRESET`, `ETIMEDOUT`, `ENOTFOUND`, `ECONNREFUSED`.
  - TLS/SSL: `UNABLE_TO_VERIFY_LEAF_SIGNATURE`, `CERT_HAS_EXPIRED`, MITM антивируса.
- Структурированный отчет:
  - Человеческое значение ошибки.
  - Подтвержденные факты.
  - Вероятная корневая причина.
  - Проверочные тесты.
  - Безопасные шаги решения с копированием команд в один клик.

### 2.3 P1: Сравнение каналов подключения (Connection Matrix)
- Параллельное тестирование целевого сервиса по 5 независимым маршрутам:
  1. *Прямое соединение (Direct)*
  2. *Системный прокси Windows (WinINet)*
  3. *Переменные окружения (HTTP_PROXY / HTTPS_PROXY)*
  4. *Защищенный DNS (Cloudflare DoH)*
  5. *Виртуальный туннель (VPN / TUN)*
- Сравнительный вердикт, объясняющий, почему трафик идет в браузере, но не в терминале или IDE.

### 2.4 P1 & P2: IDE & MCP Doctors
- **IDE Doctor**:
  - Инспекция конфигураций Cursor, VS Code, Windsurf, Zed, JetBrains, Google Antigravity.
  - Проверка параметров `http.proxy`, `http.proxyStrictSSL`.
- **MCP Doctor**:
  - Инспекция `claude_desktop_config.json`, Cursor MCP, Antigravity MCP.
  - Валидация JSON, проверка наличия исполняемых файлов в PATH (node, python, npx), валидация транспортов stdio и SSE.

### 2.5 P2: Safe Fix Engine (Безопасное устранение неполадок)
- Разрешенный список (Allowlist) недеструктивных системных операций:
  - `Flush DNS`: Очистка системного кэша резолвера (`ipconfig /flushdns`).
  - `Clear Stale Proxy Env`: Очистка сломанных переменных `HTTP_PROXY=53200`.
  - `Sync Env Proxy`: Синхронизация переменных окружения с рабочим системным прокси (`127.0.0.1:10809`).
- Окно предварительного просмотра (Dry-Run): показ точной команды перед выполнением.
- Обязательное подтверждение пользователя с фиксацией контрольной точки отката (Snapshot ID).

## 3. Архитектура и безопасность

- **Стек**: Rust + Tokio + Reqwest (rustls) + Rusqlite + Tauri 2.0 + React 18 + TypeScript + Tailwind CSS.
- **Принцип безопасности**: *Read-Only Diagnostics By Default*. Приложение никогда не производит скрытых изменений в реестре, сетевых адаптерах или брандмауэре без явного подтверждения пользователем в модуле Safe Fix.
- **Тестовое покрытие**: 13 unit-тестов в бэкенде Rust покрывают все сценарии ошибок и детекции сбоев.
